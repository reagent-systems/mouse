## Gestures

One law decides every input conflict between the shell and container content:

> **One-finger horizontal drags and all two-finger gestures belong to the shell, everywhere. Content gets taps, vertical scrolling, and the keyboard.**

One refinement to "the keyboard": while the editor is **focused**, every drag on it is a text
interaction — extending a selection by its handles, steering the caret — so the shell stands
down on that container, whatever the drag's direction. (Without this, dragging a highlight also
drove the lane: a full re-render per frame — CPU pegged — and a container swap on release.)
Other lanes and the screen-edge strips keep their swipes; tap outside to dismiss the keyboard
and the lane's swipe returns to the shell.

The shell's vocabulary (unchanged no matter what a container shows):

| Gesture | Owner | Meaning |
|---|---|---|
| One-finger horizontal drag on a lane | Shell | Swipe the lane to the next/previous container on the ring |
| One-finger drag from a screen-edge strip (32pt) | Shell | Swipe the whole ring — travel to a neighbouring ring, or mint a new one. The ring dots below the containers show the strip (current ring filled) |
| One-finger vertical drag on a divider handle | Shell | Resize the two adjacent lanes |
| Two-finger spread / pinch | Shell | Open a new lane / close a lane. Pinching the **last** lane closes the whole ring (landing on the left neighbour); closing the final ring replaces it with a fresh one |
| Tap, one-finger vertical drag inside a lane | Content | Whatever the container wants |

Per container:

- **GitHub** — taps only (buttons, tap-to-copy the device code).
- **Files** — vertical scroll moves through the tree; tap a folder to expand/collapse, tap a file to open it in the Viewer. Swiping the lane away works from anywhere on the tree, because the tree never claims horizontal drags.
- **Graph** — vertical scroll through the commit history; nothing else claims input yet (taps for commit detail later).
- **Viewer** — the open file, **edited in place**: tap the text and the caret lands under your finger, the keyboard rises, and you're editing right in the lane — no overlay, no mode. The spacebar-trackpad steers the caret; drag the text downward to dismiss the keyboard. Changes autosave (debounced ~0.8s) and flush on file switches and backgrounding. Lines wrap instead of panning horizontally (horizontal is the shell's), and text can't pinch-zoom (pinch is lane management) — font size will be a setting. The deck ignores the keyboard; the editor scrolls its caret into view within its own container. (A possible future refinement: stretch the editing container while the keyboard is up.)
- **Terminal** — tap anywhere in it to focus the prompt and raise the keyboard; typing goes to the prompt (spacebar-trackpad steers); scrollback is a vertical scroll that follows new output; output wraps like a real terminal, so it never wants horizontal panning. The top-left chip switches engines (a tap, per the law).

**How the law is enforced** (`CarouselLane.swipe`): scrollable content is UIScrollView-backed, and UIScrollView claims every drag that starts on it — so the lane swipe attaches as a *simultaneous* gesture (which scroll views can't block) and arbitrates itself: at first movement each drag locks to an axis, horizontal-dominant drags drive the lane while the gesture stands down entirely for vertical ones. Result: vertical scrolls content, horizontal swipes the lane, from anywhere on any container. The focused-editor stand-down rides the same arbitration: the Viewer mirrors its focus onto the deck (`@FocusState` → `deck.editorFocused`, reset on keyboard-hide as a backstop), and while it's set, drags on the viewer lane lock to the content side unconditionally.

Other consequences the law creates: the keyboard shrinking the deck is shell behavior (lanes re-fit, same as divider changes); the edge strips must yield drags that are clearly vertical so tree-scrolls starting near the screen edge aren't eaten (known gap, to fix with the terminal phase); text-selection handle drags belong to UIKit's text interactions, which sit deeper than the lane gesture.

## Functionality

The model lives in `Mouse/CarouselDeck.swift`, the interaction layer in `Mouse/ForegroundView.swift`.

- **Ring** (`CarouselDeck`) — a circular set of container instances. The screen is a window over it: on-screen instances sit in **lanes**, the rest in the ordered off-screen `reserve`. Swiping a lane pulls the next instance in from one shared edge and pushes the old one off the other, so instances shuffle freely between lanes.
- **Ring strip** (`RingStrip`) — an ordered list of rings; exactly one is on screen. Dragging from a screen-edge strip swipes the whole ring: to the neighbouring ring on that side, or — when the strip ends there — a freshly minted single-lane ring (container 1, rest of the catalog in reserve). A fresh ring only joins the strip if the swipe commits.
- **Container instance** (`ContainerType`) — one spot-holder on a ring, identified per-instance; a ring may hold several instances of the same catalog `kind`.
- **Container content** (`ContainerContent`) — what's inside, reference-typed and separate from the instance. Kinds in `ContainerContent.syncedKinds` resolve to a single app-wide object, so every instance of that kind, across all rings, shares (and live-updates from) the same state. Other kinds get private content per instance. To sync more kinds, add them to that set.
- **Onboarding ring** (`CarouselDeck.onboarding()`, preset kinds ≤ 0) — first launch opens a dedicated, isolated ring of lesson containers (blank fillers + one lesson at a time; empty reserve, so nothing else swipes). No arrows anywhere: each lesson's `idle` animation suggests its gesture, and the label flips to past tense live, mid-gesture, via the content's `done` flag. The chain: **Swipe?** (horizontal bounce; "Swiped." past the commit threshold; retires once swiped, handing its lane to) → **Drag?** (label rides the divider gap; gap-reach idle — both sides of the gap move the SAME direction via the deck's shared `dragPulse`, so the boundary itself visibly travels up and back; "Dragged." mid-drag, then morphs into) → **Spread?** (same gap label; gap-breathe idle — both sides retreat in OPPOSITE directions via the shared `spreadPulse`, widening the space as a bounce; the two-finger spread opens a new lane, which arrives blank and only takes on) → **Pinch?** (after "Spread." has left the stage; shrink pulse; flips to "Pinched." and removes itself when pinched closed) → **Edge Swipe?** (rotated label in the ring's right gutter — rendered inside the stack, so it gets dragged along with the ring as the user swipes it away; "Edge Swiped." mid-drag). The drag lesson's word rides its boundary pulse; the spread word holds still while its gap breathes. Lessons appear strictly one at a time — the edge lesson waits until no lesson container is in the lanes at all — and gap labels live outside the container, so idle animations never move them. Every lesson word uses the same type (IBM Plex Mono, 28pt, black when outside a container); the layout makes room for the words rather than shrinking them: dividers grow to `lessonDividerHeight` while a gap-label lesson is up (lanes re-fit automatically), and the side gutters widen during the edge lesson to fit the rotated label. The edge swipe creates the user's first real ring, and the onboarding ring retires behind them once the transition settles. All lesson states persist (`done` in `InstanceSnapshot`, `isOnboarding` in `RingSnapshot`); a lesson saved mid-morph restores as its successor.
- **GitHub container** (`Mouse/GitHubAuth.swift`, catalog kind 1) — the first real container: sign in with GitHub via the OAuth Device Flow against a classic **OAuth App** with `repo` scope: the token acts as the user — every repo they can touch, no installation step, no expiry (a 401 signs out cleanly; there is no refresh dance). A GitHub App provider existed briefly and was removed — its install-and-approve model 403'd ordinary personal use; restore from history if an org ever needs narrow permissions. The container shows a code to enter at github.com/login/device (tap to copy, button to open), polls until authorized, then shows `@login`. Tokens (access + refresh) live in the Keychain; the login handle is cached for instant restore and the session re-validates in the background (refresh-once on 401, sign-out if that fails, offline keeps the cached session). Sign-in state is app-global — every instance of the GitHub container in any ring reflects the same session.
- **Workspace** (`Mouse/Workspace.swift`, `Mouse/WorkspaceViews.swift`) — a project: a working tree on local disk plus shared project state. **One workspace per repo, app-wide**: rings opening the same repo share the same object (tree, dirty set, sync state, graph cache stay in step), while each ring keeps its own *viewport* — open file and terminal session — so several rings on one repo are several editors over one project: swipe between rings to switch files. The **Files container** (kind 2) starts projects: "+ new local project" (an empty tree on this device, born with a local git repo — commit/branch/merge work at once, and `sync` publishes it to GitHub on first push), the existing local projects, and the signed-in user's repos, downloaded via GitHub's tarball API (native gunzip + tar extraction — ustar/GNU-longname/pax, shared infrastructure for the future package manager). The tree browses by vertical scroll (tap folders to expand, tap a file to open) and ends with "+ add file": name a file (subfolders in the name are created), it lands empty, marked modified, and opens in the viewer. The **Viewer container** (kind 3) shows the workspace's open file: mono, line numbers, wrapped lines (no horizontal panning per the gesture law), read-only for now. Ring ↔ workspace association and the open file persist; a missing tree falls back to the repo picker. Real containers (GitHub/Files/Viewer) render black, terminal-styled. libgit2 (real clones, status, commits) arrives with the Source Control phase.
- **Git module toolbar** (`GitModuleToolbar` in `Mouse/GitGraphView.swift`, plus `Mouse/GitHubPush.swift`) — a fixed row of five labeled controls in the Graph container's header, beneath the `owner/repo history` title: **`commit · sync · branch · merge · refresh`**. They pre-exist and **dim** (white at 0.28) until each one's prerequisite is met, then brighten — a tap on a dimmed control isn't dead, it says why in the ring's terminal (`commit: nothing to commit, working tree clean`). **commit** (native `GitCore.commitAll`, enabled when the worktree differs from HEAD) prompts for a message and lands the whole worktree as one commit. **sync** pushes: for a repo with a local `.git` it publishes local commits via `GitRemote` (creating the GitHub repo on first push). Sync never pulls — the app must not rewrite a user's files on its own; bringing down remote commits is the explicit `git pull` in the terminal, which fetches incrementally (`have` negotiation), merges with the native engine, and refuses to run over uncommitted edits. For a downloaded (tarball) repo sync commits the modified files via the Git Data API when there are edits, else re-downloads the latest tree. It's the one control with in-flight state — a spinner while running, a red tint on failure — and its failure reason lands in the terminal. **branch** (enabled once the branch has a commit) switches between local branches or creates a new one. **merge** (enabled at two or more branches) three-way-merges a chosen branch into the current one via the native merge engine — fast-forward when possible, a merge commit for clean divergent edits, or conflict markers written to the worktree (the files are marked modified; resolve and commit). **refresh** (always usable — its only prerequisite is a workspace) re-derives the toolbar's enablement, re-checks the remote head, and rebuilds the graph, bypassing the dedupe stamp and the upstream throttle that automatic refreshes lean on. Failures and outcomes narrate to the terminal, the app's one honest error surface; the dirty set persists across launches.
- **Graph container** (`Mouse/GitGraphView.swift`, kind 4) — the git module: the workspace's commit graph plus the git toolbar (above). The graph is colored branch rails with lane assignment computed from parent topology (newest-first; a commit lands on the rail expecting it, other expecting rails curve in and close, merge parents fan out or connect to existing rails), filled dots for commits, rings for merges, branch tips as capsule labels. History is LOCAL (from `GitCore`, full branch topology, no network) whenever a `.git` exists, else the GitHub API for downloaded repos. Vertical scroll only.
- **Terminal container** (`Mouse/Terminal.swift` + `Mouse/Shell.swift`, kind 5) — switchable engines behind one prompt (the top-left chip cycles them). **`msh`** is a from-scratch POSIX-flavored shell (iOS has no fork/exec — the a-Shell model) with a real language (`Mouse/ShellLanguage.swift`: lexer, AST, parser; the evaluator lives in `Shell.swift`): control flow (`if`/`elif`/`else`, `for`, `while`/`until`, `case` with `|` patterns, functions with `$1…$# $@`, `local`, `return`), command substitution (`$(…)`, backticks, nesting), arithmetic (`$((…))` with variables and comparisons), parameter operators (`${X:-def} ${X:=} ${X:+} ${#X} ${X#pat} ${X##} ${X%} ${X%%}`), field splitting and globbing of expansion results, quoting (`'…'`, `"…$VARS"`, `\`), variables (`$NAME`, `$?`, `$$`, `export`/`env`/`unset`, `NAME=value` prefixes scoped to their command), tilde and globs (`~ * ? [abc]`, matched against the workspace), pipelines (`|`, compounds allowed as elements — `… | while read x; do …; done` works), redirection (`> >> <`, including on compounds: `done < file`, `fi > out`), sequencing (`; && || !`), `test`/`[`, `read`, `set -e -x -o pipefail` and `set -- args`, `shift`, `break`/`continue`/`exit`, `eval`, `source`/`.`, script execution (`sh file args`, `sh -c 'cmd'`, `./script.sh` via shebang, `curl url | sh` — the install-script shape), comments and line continuations, and history (`history`, `!!`, `!N`). The language is verified against **real `/bin/sh`**: a 25-script corpus (control flow, functions, expansions, `set -e`, `while read`, an install-shaped script) runs through both shells with stdout and exit status compared (method in AGENTS.md). **`npm` / `pnpm` / `npx` are real** (`Mouse/PackageManager.swift`, phase F of system.md): `npm install [pkg[@range]]` resolves against the npm registry (full semver ranges), verifies tarball integrity (sha512), unpacks natively (`TarGz`), lays out a Node-compatible hoisted `node_modules`, records executables in a manifest, and updates `package.json`; `npm install` with no args installs from `package.json`, `npm ls` lists the tree, `npx <pkg>` installs and resolves the package's bin. Resolution is verified identical to `pnpm install --lockfile-only`, and the installed layout is proven by real `node` requiring packages from it. **`node` is real too** (`Mouse/NodeEngine.swift`, phase G core): a Node-compatible runtime on JavaScriptCore — the CommonJS module system over `node_modules` (package.json `main`/`exports`/index, node_modules walk-up, module cache), core modules (`fs` with sync/callback/promises forms, `path`, `os`, `util`, `events`, `buffer` with utf8/hex/base64, `tty`, `assert`, real `crypto` (CryptoKit digests/HMAC, CSPRNG randoms, **real ciphers** — AES-GCM/CBC/CTR and ChaCha20-Poly1305, byte-identical to node's and interoperable with it — plus `pbkdf2`, `hkdf`, and **real signing** — RSA (PKCS1v15 and PSS, plus OAEP encryption) through SecKey, ECDSA over P-256/384/521 and Ed25519 through CryptoKit, so `jsonwebtoken` issues and verifies RS256/PS256/ES256/HS256 tokens that real node accepts), real `zlib` (libz gzip/deflate/raw in sync, callback, and **streaming** forms — a live `z_stream` per coder, so `createGunzip()` fed chunk-by-chunk works), real `readline` (TTY line editing, `question` incl. promises), real `stream` — Readable/Writable/Duplex/Transform/PassThrough with paused-vs-flowing modes, pipe with backpressure, `finished`/`pipeline` (+ promises forms), async iteration, `Readable.from`, and `fs.createReadStream`/`createWriteStream` on top), a real event loop (timers, intervals, immediates, `process.nextTick` ordered before promise reactions), Node-shaped `process` (argv/env/cwd/exit/stdout/stderr/stdin), and workspace-virtual paths ("/" is the project root, like msh). `node file.js`, `node -e`, installed package bins by name, `npx <pkg>`, and `#!/usr/bin/env node` shebangs all execute. Pack inflate uses libz (`-lz`) for exact zlib-member delimiting. **Streaming & interrupt**: a solo command may stream output over time (`ping` without `-c` emits a line per second); any keypress at the prompt interrupts it — the phone's Ctrl-C (input is refused mid-run anyway, so a keystroke can only mean "stop").
